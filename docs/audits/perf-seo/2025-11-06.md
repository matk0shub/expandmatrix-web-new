**Test setup:** Production build (`pnpm build`) served via `pnpm start`. Lighthouse 13.0.1 (mobile/tablet/desktop emulation). Reports stored in `docs/lighthouse/reports/{mobile,tablet,desktop}.json`.

## Key Findings

### 1. Largest Contentful Paint (LCP) & TTI remain slow on mobile
- Simulated LCP 13.6 s / TTI 13.6 s on mobile (tablet 3.7 s / 5.9 s).
- Observed (real) LCP is ~1.0 s, but the throttled simulation penalises due to heavy script and third-party payload.
- Main contributors:
  - 99 requests / 1.7 MB total transfer, with 72 requests (1.35 MB) from `https://meet.expandmatrix.com` (Cal.com embed).
  - `resource-summary`: JavaScript accounts for ~1.08 MB.
  - `unused-javascript`: `_next/static/chunks/6544…js` wastes ~33 KB; likely shared UI bundle.

**Opportunities**
- Lazy-load the Cal.com embed (currently loaded eagerly via `CalCTAButton`/`CalEmbedInitializer`):
  - Defer iframe/script injection until CTA click, or gate with `IntersectionObserver`.
  - Evaluate using Cal.com popover via API instead of full embed.
- Trim or chunk custom JS. Audit chunk 6544 to identify features that can be code-split.
- Consider inlining just the hero content above the fold while deferring heavy background effects.

### 2. Redirect chain detected
- Lighthouse reports two redirects (wasted ~750 ms): `http://127.0.0.1:3000/ → /` and `/ → /en`.
- On production domain, root likely redirects to locale. Optimise by serving locale directly when possible (e.g., configure canonical root to `/en` or use domain-level locale detection to avoid extra round-trip).

### 3. Third-party cookies & best-practice penalties
- `third-party-cookies`: Cal.com sets `__Secure-next-auth.*` cookies.
- Best Practices score (0.77) is mostly impacted by this and the unused JS warning.
- Evaluate whether these cookies are required pre-interaction. If not, defer the embed or use Cal.com’s headless API to avoid loading their authentication bundle until necessary.

### 4. Accessibility regression — navigation toggle button
- `button-name` audit flagged `header.absolute > … > button.lg:hidden` (mobile nav toggle) lacking accessible name.
- Fix by adding `aria-label` or accessible text to burger menu button.

### 5. Caching & asset weight
- `cache-insight`: inefficient cache lifetimes (est. savings 34 KiB). Ensure CDN/Next headers set long max-age for static assets.
- Total byte weight still high (1.7 MB). Focus on third-party reduction plus image optimisation (verify hero background assets, e.g., matrix animations).

### 6. Build-time lint warning
- `pnpm build` logged `ESLint: Config (unnamed): Key "plugins": Cannot redefine plugin "@next/next".`
- Review `eslint.config.cjs` to avoid adding the same plugin twice; resolve to keep CI clean.

## Recommendations & Next Steps

1. **Cal.com embed refactor**
   - Replace eager embed with lazy strategy.
   - Consider using Cal.com inline widget only after user intent.
   - Track impact by rerunning mobile Lighthouse after change; target LCP < 3 s.

2. **Navigation accessibility**
   - Add descriptive label to mobile menu toggle (e.g., `aria-label="Open navigation"`).
   - Re-run accessibility scan to confirm 1.00 score across profiles.

3. **JS budget & code splitting**
   - Investigate chunk `6544.08de03745b2d2ce4.js` (likely bundling hero animations). Dynamic import/`lazy()` features above the fold can reduce main bundle.
   - Enable bundle analyzer (`ANALYZE=true pnpm build`) to inspect heavy chunks.

4. **Caching improvements**
   - Ensure static assets served with `Cache-Control: public, max-age=31536000, immutable` via Next config / CDN.
   - Confirm Cal.com resources respect caching or reduce reliance.

5. **Redirect optimisation**
   - For production hosting, configure root domain to render default locale without intermediate redirects where possible.

6. **Maintain audit history**
   - Keep Lighthouse JSONs under version control (already stored) to track progress.
   - Schedule routine re-runs after major UI changes.
